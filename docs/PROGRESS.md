## Gotchas

- Corpus rows live in `matches` with kind='corpus' — every tracked-player query filters kind='own' (store tests enforce).
- Death-tick inventory always empty (pre-death sampling); steamids as strings at JS boundaries; demoparser two-pass + targeted inventory pass; numeric round reasons winner-relative; MM vs GOTV dialects.
- AX E2E: pause before reading; **a stale dev binary can serve clicks after an edit — kill + relaunch `tauri dev` before trusting E2E results**; round chips are radio buttons; canvas invisible to AX; `.claude/` excluded from git/eslint/vitest.
- Bash tool cwd persists — a `cd` into a worktree leaks into later commands; use absolute paths or cd back.
- Fresh-clone/worktree demoparser build can stall on a nested cargo lock — reuse an existing target dir (`CARGO_TARGET_DIR=<main checkout>/src-tauri/target`; a V1.2b worktree built in 10 s that way).
- AX on the Tauri WebView: `entire contents` can come back empty after focus changes — walk `UI elements` recursively by `role`; the window clamps to the Dock's visible frame (1440×888 on the owner's display) — auto-hide the Dock for a true 1440×900 capture, then restore it.
- Coach dev key: the debug loader reads `<crate>/../env.local` = the *worktree* root when running from a git worktree — `ln -s <main checkout>/env.local <worktree>/env.local` (gitignored; remove after). A 45 s "Testing…" that ends in "Couldn't reach Gemini (error sending request…)" with the socket ESTABLISHED is Google not answering (3.7-flash 503 "high demand" during the V1.3 verification), not the key — switch the models to `gemini-3.5-flash-lite` in Settings.
- CI: protoc via arduino/setup-protoc; pnpm pinned via packageManager; `source "$HOME/.cargo/env"`.
- glib RUSTSEC (Dependabot #1): fix needs gtk-stack 0.19+ semver-major held by Tauri — Linux-only exposure (we ship mac/Windows); re-check on Tauri upgrades.
- **UI automation on this Mac:** drive the app only through the accessibility API on named elements (AXPress/click by name), never blind coordinate clicks, and never while a system dialog could be up — during V1.4 a TCC prompt was answered by automation and macOS revoked the terminal's `~/Documents` access mid-session (fix: grant Ghostty Full Disk Access / Documents, then fully relaunch Ghostty). Launch the dev app for screenshots from a detached, non-sandboxed process (a Monitor-launched instance could not read demo files).
