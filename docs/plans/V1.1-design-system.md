# V1.1 Design System ("The Film Room") Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild ClutchFactor's visual identity from tokens up — fonts, token system, `ui/` component library, one AppShell with sidebar nav, MatchHeader — and rebuild all six screens on it, deleting the legacy stylesheet.

**Architecture:** Plain CSS custom properties (no framework, no new runtime deps) split by concern (`tokens/base/components/screens`), bundled OFL fonts, a single `theme.ts` bridge so canvas/TS code reads the same tokens as CSS. Screens migrate incrementally behind a shared shell: the token layer lands first (re-skinning old CSS via kept variable names), then components, then the shell swap, then screen-by-screen rebuilds, and `styles.css` is deleted last.

**Tech Stack:** React 19 + TS + Vite, vanilla CSS, vitest (node env — pure-module tests only, NO component-test infra, do not add jsdom/RTL), Tauri 2.

**Spec:** `docs/design/design-system.md` (the binding reference — read it FIRST, every value comes from it). Frontend inventory facts cited below were verified 2026-08-22 on main @ c2ad097.

## Global Constraints

- **The spec is `docs/design/design-system.md`.** Token names/values, type scale, spacing, radii, motion, the chalk-annotation grammar (§5: dashed = evidence, nothing decorative may be dashed), component variants (§6), shell (§7), per-screen notes (§9) are all defined there — tasks below reference sections instead of restating values. A conflict between this plan and the spec resolves to the spec.
- **Process (charter, absolute):** before writing ANY screen's code, the implementer invokes `frontend-design:frontend-design` via the Skill tool with that screen's brief (given in the task); before ANY chart code, also `dataviz`. Task reviews check screens against the spec doc.
- CT `#4aa3ff` / T `#f5b83d` are side identity ONLY (spec §2 rules). The app accent is chalk. Severity stays `--loss`-derived.
- No new runtime dependencies. No CDN anything — fonts are vendored with their OFL license files (ADR-0007).
- Frontend checks before every commit: `pnpm typecheck && pnpm lint && pnpm test:run`. Existing tests must stay green (importQueue, trends, replay math, etc.).
- Every screen, when rebuilt: skeleton loading (no bare "Loading…" sentences), §7-voice errors, visible focus (the ONE chalk-bright ring), holds at 1200×760, no layout shift on data arrival.
- Conventional commits. PR groups (branch → `gh pr create` → `gh pr merge --auto --squash` → verify merged; `gh pr update-branch` if BEHIND): **PR A** = Tasks 1–2 (`feat/v1.1-design-system`, this branch — the design doc is already committed on it), **PR B** = Tasks 3–4 (`feat/v1.1-ui-components`), **PR C** = Task 5 (`feat/v1.1-shell`), **PR D** = Tasks 6–7 (`feat/v1.1-screens-library-report`), **PR E** = Tasks 8–9 (`feat/v1.1-screens-replay-trends`), **PR F** = Tasks 10–12 (`feat/v1.1-screens-corpus-settings-finish`). Later branches cut from origin/main after the prior PR merges.
- Mid-milestone main is allowed to look transitional (old components on new tokens) but must never be broken: every PR leaves the app fully functional.
